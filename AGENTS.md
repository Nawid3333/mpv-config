# Agent handoff notes for this mpv config repo

This repository is for a Windows mpv setup tuned for a Radeon RX 9070 XT. The goal is a portable, reproducible configuration for anime/movie viewing with GPU shader presets, and menu-driven toggles. (Frame interpolation was removed 2026-09-20.)

## Quick orientation

- Main config: `portable_config/mpv.conf`
- Keybinds + uosc menu entries: `portable_config/input.conf`
- Runtime script logic: `portable_config/Scripts/gpu-toggles.lua`
- UI script: `portable_config/Scripts/uosc/`
- Shaders (only the 10 the presets use): `portable_config/shaders/`
- mpv's build: pinned in `mpv-build.json`, installed by `installer/install-mpv.ps1`; `updater.bat` (= `installer/update.ps1`) pulls, installs the pin and updates yt-dlp
- Rebuild instructions: `RECREATE.md`
- Settings that differ per PC + the Welcome menu (F1): `portable_config/Scripts/settings.lua` (+ `welcome.lua`); upscaling quality/screen/measurement in `gpu-toggles.lua` - see "Settings per PC" under Key runtime features
- One-click install for OTHER PCs (no git, no admin, no Node.js install): `installer/setup.ps1` (`install.bat`), updated by `updater.bat` through `installer/sync-config.ps1`, removed by `uninstall.bat` - see "One-click install" under Key runtime features

## Important conventions

- Keep config changes portable and self-contained. This project expects a repo layout next to `mpv.exe` and a local `.venv`.
- Prefer editing the source config and script, not generated runtime caches.
- Keep menu entries and keybinds aligned with the underlying `gpu-toggles.lua` script messages.
- `input.conf` entries with `#!` comments are used by uosc as menu actions; changing them changes the UI.
- `gpu-toggles.lua` is the single source of truth for the shader cycle.

A new feature gets a test (`tests/README.md` says how) and a deliberate break of it must make that test fail. CI runs static + headless on every push (`regression-tests.yml`). Items 1-8 below are what the suite automates; they stay as the reasoning.
1. `portable_config/input.conf` still parses without obvious syntax errors
2. `gpu-toggles.lua` registers a key binding (`mp.add_key_binding`) for every name `input.conf` reaches via `script-binding gpu_toggles/<name>`, and a script message (`mp.register_script_message`) for every name reached via `script-message-to gpu_toggles <name>` - these are not interchangeable, see bug #1 above

Write colours as `r/g/b/a` or `gray/a` (`0.0/1.0` = opaque black) or quote them. Caught twice now: the static check "no '#' inside a value" and the headless `config-load` check, which starts the real mpv with the copied config at `--msg-level=all=warn` and fails on ANY line it prints (a bad value, a renamed option after an mpv update, a script error at load). When probing by hand, read the property back instead of trusting the config line.
- **`mpv.conf` profile sections must stay at the END of the file.** Everything after a `[section]` header belongs to that profile until the next header. The `[faststream-hwdec]` profile sat mid-file from 2026-09-16 to 2026-09-21, which silently scoped the whole network-buffering block (`cache`, `demuxer-max-bytes`, `cache-pause-*`) and `swapchain-depth` to FastStream streams only - local files and other URLs ran on mpv's defaults (150 MiB buffer, swapchain 2). Found by reading the options back from a running player for four cases (local file, untagged stream, `#fs-content=movie`, `#fs-content=anime`); now all four show cache=yes, `demuxer-max-bytes=1GiB`, 128 MiB back buffer, wait 3 s, swapchain 4, and hwdec still switches per file (`vulkan` for FastStream, `d3d11va-copy` otherwise). The buffer holds compressed packets in system RAM, never VRAM (1 GiB is only a ceiling; the PC has 63 GB); the upscale shaders never touch it. Any new global option goes above the profile block.
